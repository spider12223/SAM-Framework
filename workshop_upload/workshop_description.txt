[h1]S.A.M Framework (Support All Mods)[/h1]

Mod Barony with plain files. No C++, no compiler. Write a small .json, drop it in your mods folder, and the game loads it as a real class, item, monster, spell or status effect.

[b]S.A.M is a dependency, not a playable mod.[/b] It is the thing other mods are built on. Install it once and every S.A.M mod works.

[b]READ THIS: subscribing here does NOT install it.[/b] S.A.M is a modified barony.exe, and Steam cannot replace a game's .exe by itself. You have to run the installer one time. It takes about a minute.

[hr][/hr]

[h1]HOW TO INSTALL[/h1]

[b]Step 1.[/b] Own Barony on Steam and launch the game once, so its files exist. Then close the game.

[b]Step 2.[/b] Open the download page:
[url=https://github.com/spider12223/SAM-Framework/releases/latest]https://github.com/spider12223/SAM-Framework/releases/latest[/url]

[b]Step 3.[/b] Scroll to the [b]Assets[/b] list and click [b]SAM_Framework_Installer.exe[/b]. There is only one installer and it never goes out of date.

[b]Step 4.[/b] Open your [b]Downloads[/b] folder and double click it.

[b]Step 5.[/b] If Windows says "Windows protected your PC", click [b]More info[/b], then [b]Run anyway[/b]. The installer is not code signed, which is the only reason Windows warns.

[b]Step 6.[/b] It finds your Barony folder on its own. Check the path is right, then click [b]Install[/b].

[b]Step 7.[/b] It saves your original game file as [b]barony_vanilla.exe[/b] (your backup), then puts the S.A.M version in place. Close the installer.

[b]Step 8.[/b] Launch Barony from Steam like normal.

[b]Step 9.[/b] Look at the bottom of the main menu. If you see a shield icon and [b]S.A.M Framework[/b], you are done. If not, repeat steps 3 to 7.

[b]You only do this once.[/b] To update later, run the installer again. It always grabs the newest version.

[hr][/hr]

[h1]HOW TO USE A MOD[/h1]

[b]Step 1.[/b] Get a S.A.M mod. It is a folder. If you got a .zip, unzip it first.

[b]Step 2.[/b] Put that folder in:
[b]C:\Program Files (x86)\Steam\steamapps\common\Barony\mods\[/b]

[b]Step 3.[/b] Launch Barony, click [b]Mods[/b], click the [b]Local Mods[/b] tab, then [b]Load Mod[/b] next to your mod.

[b]Step 4.[/b] Click [b]Start Modded Game[/b]. Your class or item is now in the game.

[b]Workshop mod?[/b] Subscribe, then let Steam finish downloading before you launch. If [b]Load Mod[/b] does nothing, Steam has not downloaded it yet. Close Steam fully, reopen, wait, then launch.

[b]To go back to normal Barony:[/b] delete barony.exe and rename [b]barony_vanilla.exe[/b] back to [b]barony.exe[/b]. Or verify the game files in Steam. Nothing else is ever changed, and your saves are backed up while mods are active.

[h1]HOW TO MAKE A MOD[/h1]

[b]The easy way, in your browser. Nothing to download:[/b]
[b][url=https://spider12223.github.io/SAM-Framework/]S.A.M Mod Builder[/url][/b]
Fill in the boxes, export a ready to use .zip. If it exports, it loads.

[b]By hand,[/b] a mod is a folder with a mod.json saying what it contains, then one file per thing you add. Here is a whole working weapon:

[code]{
  "id": "mymod:bone_axe",
  "name_identified": "bone axe",
  "category": "WEAPON",
  "slot": "EQUIPPABLE_IN_SLOT_WEAPON",
  "weapon_skill": "axe",
  "attributes": { "ATK": 4 }
}[/code]

That is a real axe in Barony's item table. It trains the Axe skill, shows proper damage in its tooltip, appears in shops and chests, and can be a class's starting weapon.

You can make classes, items, monsters, spells, status effects, playable races, sounds, models and tinkering recipes the same way.

[b]A JSON file says what your thing is. A script says what it does.[/b] Most mods never need a script. If you want one, drop a .lua, .js or .ts file next to your JSON and it loads by itself:

[code]function on_event(e)
  if e.name == "player.on_kill" then
    sam_message(e.player, "Another one falls.")
  end
end[/code]

56 events to react to, over 90 functions to act with. Scripts are sandboxed: a broken one switches itself off and cannot crash your game.

[b]Two example mods ship with the framework[/b] and are the fastest way to learn. One uses every capability once, the other is a full custom boss.

[h1]WHAT IS NEW IN 1.10.0[/h1]

1.9.0 let a monster wear your own model. It stood perfectly still, faced whichever way you happened to build it, and kept the hitbox of whatever creature was underneath it. [b]1.10.0 makes that model move, face you, and be the right size to hit.[/b]

[list]
[*][b]Your creature animates.[/b] Give it a list of models and it cycles them while it moves. Two frames is already enough to read as a walk or a wingbeat. Barony has no skeletons, so this is exactly how the vanilla rat animates.
[*][b]An attack frame.[/b] Name one more model and it switches to that while swinging, so players see the bite coming.
[*][b]Fix a model that faces the wrong way.[/b] One rotation number, instead of exporting every frame again.
[*][b]Put the head where the bite comes from.[/b] The game spawns attacks from the spot a creature stands on, and on a long creature that sits mid body, so a dragon looks like it bites with its belly. Slide the model back and its head lands there instead.
[*][b]Set how big it is to hit.[/b] A big model used to keep the small hitbox of the creature underneath it, so you swung at its ankles. Now you can size the box to the model, and a wide creature really does fill a corridor.
[*][b]Custom bodies work on every creature.[/b] Bats, ducks, mimics, moths and sentry bots used to show nothing at all, and everything else showed its old arms and legs poking through your model. Both fixed, so all 41 creatures are usable as a base.
[/list]

Everything above is set in the Mod Builder, with no scripting. 1.9.0's additions are all still here: custom monster models, eleven monster traits, working spell items, custom classes in multiplayer, and the scripting reference.
