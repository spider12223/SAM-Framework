[h1]S.A.M Framework (Support All Mods)[/h1]

Mod Barony with plain files. No C++, no compiler, no engine knowledge. Write a small .json, drop it in your mods folder, and the game loads it as a real class, item, monster, spell or status effect. Add a short script next to it if you want it to actually do something.

[b]S.A.M is a dependency, not a playable mod.[/b] On its own it adds nothing to play. It is the thing other mods are built on. Install it once and every S.A.M mod works.

[b]READ THIS: subscribing here does NOT install it.[/b] S.A.M is a modified barony.exe, and Steam cannot replace a game's .exe by itself. You have to run the installer one time. Steps are right below and it takes about a minute.

[hr][/hr]

[h1]HOW TO INSTALL (step by step)[/h1]

[b]Step 1.[/b] Own Barony on Steam and launch it once so its files exist. Then close the game.

[b]Step 2.[/b] Open the download page:
[url=https://github.com/spider12223/SAM-Framework/releases/latest]https://github.com/spider12223/SAM-Framework/releases/latest[/url]

[b]Step 3.[/b] Scroll down to the [b]Assets[/b] list and click [b]SAM_Framework_Installer.exe[/b]. It saves to your Downloads folder.

[b]Step 4.[/b] Open [b]Downloads[/b] and double click [b]SAM_Framework_Installer.exe[/b].

[b]Step 5.[/b] If Windows says "Windows protected your PC", click [b]More info[/b], then [b]Run anyway[/b]. The installer is not code signed, which is the only reason Windows warns.

[b]Step 6.[/b] It finds your Barony folder on its own. Check the path looks right, then click [b]Install[/b].

[b]Step 7.[/b] Let it finish. It saves your original game as [b]barony_vanilla.exe[/b] (your backup), then puts the S.A.M version in place. Close the installer.

[b]Step 8.[/b] Launch Barony from Steam as normal.

[b]Step 9.[/b] Look at the bottom of the main menu. A shield icon and the words [b]S.A.M Framework[/b] mean you are done. If it is not there, repeat steps 3 to 7.

[b]You only do this once.[/b] To update later, run the installer again. It always grabs the newest version.

[hr][/hr]

[h1]PLEASE READ BEFORE INSTALLING[/h1]

S.A.M replaces the game's program file, and we build it without a few services that need the developer's own private credentials. [b]While S.A.M is installed you lose three things: crossplay with Epic Games Store players, online leaderboard scores, and video playback (the intro and animated signs).[/b] Everything else, including Steam multiplayer, works normally.

These are not bugs we can fix. They need private Epic and PlayFab credentials that only the game's developer has. Switching back takes ten seconds, see below.

[hr][/hr]

[h1]HOW TO GO BACK TO NORMAL BARONY[/h1]

Delete barony.exe, then rename [b]barony_vanilla.exe[/b] back to [b]barony.exe[/b]. Or right click Barony in Steam, pick Properties, then Installed Files, then Verify integrity of game files.

Nothing else is ever changed. S.A.M does not edit any of the game's own files, and it backs up your saves while mods are active.

[hr][/hr]

[h1]HOW TO USE A MOD[/h1]

[b]Step 1.[/b] Get a S.A.M mod. It is a folder. If you got a .zip, unzip it first.

[b]Step 2.[/b] Put that folder in your Barony mods folder, usually:
[b]C:\Program Files (x86)\Steam\steamapps\common\Barony\mods\[/b]

[b]Step 3.[/b] Launch Barony, click [b]Mods[/b], open the [b]Local Mods[/b] tab, then click [b]Load Mod[/b] next to yours.

[b]Step 4.[/b] Click [b]Start Modded Game[/b] at the bottom.

[b]Workshop mod instead?[/b] Subscribe, then let Steam finish downloading before you launch. If [b]Load Mod[/b] does nothing, Steam has not finished. Close Steam fully, reopen, wait, then launch.

[h1]WHAT YOU CAN MAKE[/h1]
[list]
[*][b]Classes.[/b] Attributes, skills, starting gear (including your own items), starting spells, level up growth, gold, and a character select portrait with real stat bars and difficulty stars.
[*][b]Items and weapons.[/b] Real entries in Barony's item table, with category, equip slot, weight, value, ATK and AC, your own model and icon.
[*][b]Monsters.[/b] Variants of any creature with your own stats, gear, name, followers and spawn floors, plus your own model that animates as it moves and attacks.
[*][b]Spells.[/b] Custom spells that really cast, through the game's own projectile pipeline.
[*][b]Status effects.[/b] Your own named buffs and afflictions, with duration, strength, AC and damage changes.
[*][b]Playable races.[/b] Play as a monster body.
[*][b]Sounds.[/b] Ship your own .ogg files and play them from a script.
[*][b]Custom .vox models.[/b] Your own voxel models, loaded at startup.
[*][b]Tinkering recipes.[/b] Add, remove or re-cost what the tinkering kit can build.
[*][b]Vanilla patches.[/b] Edit the game's data in layers, so two mods stack instead of overwriting each other.
[*][b]Your own windows.[/b] Real panels with buttons, pictures, scrolling lists and text boxes, so a mod can have a shop, a quest log, a bestiary or a settings screen instead of just printing to the screen.
[*][b]A home you can go back to.[/b] Send the party to any floor, including back UP, which the game itself never does, and give them a chest whose contents follow them down every floor and survive saving and loading.
[*][b]Progress that belongs to one character.[/b] Save your own values inside a character's savegame, so a new character never inherits the last one's unlocks.
[*][b]Custom projectiles.[/b] Fire something with its own speed, model, damage and range, for ranged enemies, boss volleys, traps and weapons that shoot more than arrows.
[*][b]Read the game itself.[/b] List every item, monster and spell the game knows about, including anything mods added, so you can build an index or a shop from real data.
[/list]

[h1]SCRIPTING (Lua, JavaScript, TypeScript)[/h1]

JSON says what your content [i]is[/i]. A script says what it [i]does[/i]. Drop a .lua, .js or .ts file next to any class or item JSON and it loads automatically. TypeScript is compiled for you.

[b]65 events[/b] to react to. Combat, level up, death, floor change, items (equip, use, pick up, identify, break), shops, chests, traps, monsters, key presses, a per tick handler, world things (doors, levers, fountains, teleporters, projectile hits), and bound actions that follow whatever the player rebound them to.

[b]163 functions[/b] to act with. Grant items and gold at any quality, read and set stats, level a player up for real, apply and read status effects, cast spells, deal or change damage, move speed, teleport, spawn monsters and items, full monster control by id, timers, saved data that survives between runs, screen effects, and live patching that reverts when your mod unloads.

Only two functions ever get called: [b]on_event(event)[/b] and [b]on_tick(event)[/b]. Everything else arrives as [b]event.name[/b] inside on_event.

[b]Safe by design.[/b] Scripts run sandboxed with a memory cap and an instruction limit. A broken script switches itself off and writes why to the log. It cannot crash your game.

[h1]MAKE A MOD IN YOUR BROWSER[/h1]

The easiest way, nothing to download:

[b][url=https://spider12223.github.io/SAM-Framework/]S.A.M Mod Builder[/url][/b]

Build a class, item, monster, spell or effect with dropdowns and sliders, watch the JSON update live, then export a ready to use .zip. It checks your work against the same rules the game uses, so if it exports, it loads. You can import an existing mod to edit it too.

[h1]PUBLISHING YOUR OWN MOD[/h1]
[list]
[*][b]1.[/b] Build and test it locally with S.A.M installed.
[*][b]2.[/b] Put a [b]preview.png[/b] in your mod folder. That exact filename becomes the thumbnail, and the upload can fail without one.
[*][b]3.[/b] Upload the folder as a Workshop item.
[*][b]4.[/b] Add [b]S.A.M Framework[/b] as a Required Item, and tell players in your description that they must run the S.A.M installer. Subscribing alone does not install the exe.
[/list]
